# UI 阶段：页面与播放器

本轮仅补 Android 原生 UI 和支撑交互的小范围状态修改。接口、DTO、Repository、播放服务、依赖与 CI 配置保持原样。视觉参考 Apple Music 的层级与播放器结构，使用哲听品牌；未完成像素级对照或真机动效验收。

## 已写入代码

| 页面 / 组件 | 内容 |
|---|---|
| 主题与基础组件 | 中性浅色 / 深色、红色操作、高层级标题、封面占位、歌曲当前项高亮、空态和错误重试 |
| 首页 | 标题与账户入口、大封面推荐歌单、新歌列表；继续使用真实数据 |
| 搜索 | 输入框、清除、键盘搜索、结果列表与分页、空态；修复同一失败关键词无法重试 |
| 歌单 | 居中封面、创建者、可展开简介、播放全部或已加载歌曲、分批歌曲列表 |
| 资料库 | 账户、当前曲目、真实播放队列、发现音乐、关于；未接入的收藏明确说明 |
| 账户 | 游客、已登录、加载、失败与刷新；读取现有会话 |
| Mini Player | 浮动圆角条、封面、歌曲、播放与下首；按字体缩放预留高度 |
| 全屏播放器 | 封面、进度、上一首 / 播放 / 下一首、歌词切换、待播清单、横屏和小屏滚动布局 |
| 展开与收起 | Compose sharedBounds 容器过渡与 sharedElement 封面过渡；顶部 / 封面下拉按距离或速度收起，否则回弹；点击和系统返回收起 |
| 歌词组件 | 按行排版、当前行、点击 seek、自动跟随、手动滚动后回到当前行；只在 debug 预览提供样本 |

共享元素依据 [Compose 官方文档](https://developer.android.com/develop/ui/compose/animation/shared-elements)，在同一 SharedTransitionLayout 内连接 Mini 与全屏；弹簧参数是本项目的初始调参值。

## 数据边界

- 真实歌词请求、LRC 解析及缓存仍属于后续数据接入。全屏的歌词模式目前显示“当前版本暂不支持歌词显示”，没有伪造歌词或自动生成歌词。
- 二维码登录、个人收藏歌单、播放历史仍未接入，不展示虚构的用户数据。
- 关于页只说明现有“随系统切换深浅色”的行为，不提供未持久化的设置开关。
- 播放、队列、seek 继续使用服务的 PlaybackController。UI 展开和关闭不重新创建播放器。
- 未新增整屏实时模糊、取色线程、后台动画或图片处理依赖；低端机是否流畅仍需实测。

## APK 验收（待执行）

1. CI 执行 testDebugUnitTest、assembleDebug、lintDebug；安装新 APK。
2. 首页歌单进入详情，播放一首；搜索歌曲，整队播放；资料库打开当前队列并跳播。
3. Mini 与全屏连续开合 10 次，检查封面无双影 / 闪白、列表不跳动、声音和暂停状态不变。
4. 展开途中返回、慢拖回弹、快甩关闭、收起途中重新展开；检查封面 / 容器反向过渡，特别确认下拉松手接共享收起没有位置跳变。
5. 播放器空白处点击不穿透到底下页面；系统返回先关闭队列，再关闭全屏。
6. 进度拖动不触发收起，换曲后拖动预览清空；未知时长不能 seek。
7. 320dp 宽、1.5 倍字体、横屏、深浅色、手势 / 三键导航下无裁切；TalkBack 可找到各个按钮。
8. 慢网 / 封面失败、搜索首屏失败重试、部分歌单加载失败、游客会话、空队列均有可读状态。
9. 录屏验收过渡；当前没有真机帧率、内存或动画连续性的合格结论。
